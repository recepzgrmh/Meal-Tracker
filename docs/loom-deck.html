Live demo

Three moments

Uncertainty is surfaced

Type biraz beyaz peynir — “a bit of white cheese.” The server flags the amount as uncertain instead of silently guessing. Pick a portion, commit, it lands on the dashboard.

No match is a real answer

A food the catalog does not carry returns an explicit NO_MATCH. Manual search first; when nothing fits, the server returns a labelled, bounds-checked estimate — persisted server-side, never supplied by the client.

Photos get no special trust

Camera to private per-user storage, vision extraction, then the same grounded matching path as text.

Why hallucinated nutrition is structurally impossible

Four gates, not one prompt

  1. Response schemaStrict JSON schema; candidateId is an enum of retrieved IDs.
  2. Server re-parseEvery field re-validated and bounds-checked after the model replies.
  3. Cache re-validationA cached selection is re-checked against the current allow-list before reuse.
  4. Commit RPCNutrition re-read from foods in-transaction; a client sending forged macros is rejected by a passing test.

Measurement

Two instruments that measure different things

Regression gate · free, in CI

60/60   F1 1.00   portion MAPE 0

Runs the parsing path against a three-food fixture catalog with no network, no retrieval, no model. The perfect score means one thing: no regressions in Turkish parsing. It says nothing about product accuracy.

Live eval · paid, product accuracy

20 bilingual cases through the deployed function, reporting latency, tokens, cache hits and cost per case.

Every run persists to eval_runs / eval_cases, so results are inspectable in the console afterwards rather than scrolling past in a terminal.

What the harness caught

A defect every other gate missed

Candidate grounding is unavailable:
function pg_catalog.coalesce(numeric, integer) does not exist

COALESCE, GREATEST and LEAST are parser constructs, not catalog functions. Schema-qualifying them turns each into a missing-function lookup at execution time. Two deployed functions carried it: the daily cost ceiling, which runs immediately before grounding, and the commit RPC — so every analysis failed as a provider outage, and every analyzed-meal commit would have failed the moment a user saved.

Why it survived. Valid SQL, so lint accepted it. Unit tests mock fetch, so they never reach Postgres. The database test needs a local stack that had not been run.

What changed. The repair asserts the pattern is gone instead of replacing one instance, and a test keeps the guard in the suite — an earlier migration had fixed this once already and later work reintroduced it.

Reliability

Two things I can show, not just claim

Replay the same commit twice

The second is a no-op. An advisory lock plus a unique request key means a retry after a partial failure cannot duplicate a meal.

Airplane mode, then back

The meal is written locally and queued in a Drift outbox with backoff and blocked-state handling, then syncs. Covered by tests, not only demoed.

Observability

Every run is accountable

Recorded per analysis: model, prompt version, retrieval version, latency, input and output tokens, cache hits, vision fallback reason, error code, and estimated cost in micro-dollars. Raw meal text stays out of standard logs.

Failure, by stage

Daily runs and failures with an error breakdown, so “what broke today” is a query rather than a guess.

Spend, per model

Token and cost telemetry per prompt version, with a daily ceiling enforced before any paid call.

Corrections

Commit-time diffs record what users repaired — the production accuracy signal that thresholds should eventually be calibrated against.

Limits I would fix next

What I already know is wrong

Portion estimation

The weak half of the measurement, and the first thing I would attack once labels are trustworthy.

Uncalibrated thresholds

Confidence gates are hand-picked constants; correction rates are the signal to calibrate them against.

Analyze duplicate race

A tight concurrent window can double-run the pipeline and double provider spend. The commit path is unaffected.

p95 latency

13.4 s at the tail is a product problem independent of accuracy.

Next: review and re-label the identity failures, re-measure against a trustworthy baseline, calibrate thresholds from correction rates, and move embedding backfill out of the request path into a scheduled worker.

Nutrition cannot be invented here — and where it has to be estimated, it is labelled and bounded.
